# 个人微信接管 — 现有流程盘点与复用边界（2026-11-18）

> 背景：这轮排查把"开会话"反复重写，越改越偏。这份文档把**引擎里已有的流程**一次列清，
> 明确哪些必须复用、哪些才该交给模型/robot，避免再逐条试错。

## 一、总原则

```
引擎 = 手（原语）：怎么找人、怎么开会话、怎么读会话、怎么发、怎么验
robot/Agent = 脑子：什么时候调哪个原语；原语失败时观察→换招→再验
```

- **robot 不再重新实现"找人 / 开会话 / 打字 / 校验"**，只调用引擎原语。
- 引擎原语必须是"自带验证"的：成功与否看**可见记录**，不看动作是否执行。
- 现有流程里已经写了大量"平台特性"（同名群、资料卡读不到、wxid 唯一、限速闸门），这些**不能丢**。

## 二、流程清单（60 个公开函数，按领域归并）

| 领域 | 入口 | 机制 | 验证方式 | 现状 |
|---|---|---|---|---|
| 会话同步 | `sync_local_sessions` | wxauto4 时间快照 + 翻页（`max_pages=12`），扫的时候顺带抓消息 | 每行有精确时间戳才入库 | 可用（4.1.7）；4.2 无 UIA 不可用 |
| 历史消息 | `sync_local_messages` | 打开会话读消息列表 | 与库内 last_id 去重 | 可用 |
| 通讯录同步 | `sync_local_contacts` | 键盘走列表（`_CONTACT_KB_STEPS_*`）+ 右侧资料卡核对 | 名字必须能对回当前行才写库 | 可用；慢（上万联系人） |
| 群/群成员 | `sync_local_groups` / `sync_local_group_members` | 通讯录 → 群聊 → 成员列表 | 群名与成员行核对 | 可用 |
| 好友申请 | `accept_local_friend_requests` | 「新的朋友」页 UIA 行 + 接受按钮 | 行状态变成「已添加」 | 可用，自带限速（≤8/批、≤4/日、间隔≥2h） |
| 加好友 | `add_local_friend` + `create_add_friend_task` | 搜索 → 加好友表单 → 提交 | `_classify_local_add_friend_failure`（已是好友/未进表单/搜不到） | 可用，失败原因已分类 |
| 发消息 | `_send_text_local_slow` | 打开会话 → 写入输入框 → 回车 | 可见消息快照出现该文本 | **写入环节在微信 4.x 自绘输入框读不回 → 被拦** |
| 朋友圈 | `publish_moments_local` / `create_moments_*_task` | 4.x 点「发表」先弹系统选图框 | 任务 steps + 回读 | 发布入口已摸清；点赞/评论靠坐标（UIA 无控件） |
| 群发/群任务 | `create_group_task` | 批量选择 + 逐条发送 | 同上（可见记录） | 可用 |
| 诊断 | `diagnose_local_wechat_ui` | UIA/窗口健康检查 | — | 可用；**不要放进诊断包**（会把打包挂死） |

## 三、已有的"平台特性"清单（不能丢）

1. **wxid 唯一**：找人一律先按 wxid 搜，名字只做兜底（同名群：军争 / 军争、单鹏程 / 单鹏程、军争 …）。
2. **只点「联系人」分组**：`selection_scope=联系人:first_matching_result`。
3. **打开后按显示名核对**：`_verify_local_send_chat`，不一致就拦（防止发错人/发到群）。
4. **chat_type 不可信时回落本地库**：`wechat_peers.chat_type`；`unknown` 不等于"非私聊"。
5. **预览文本不能当群聊判据**：`sender: text` 会误伤"robot自开会话 12:27:48"这类含时间的单聊。
6. **限速闸门**：好友申请 ≤8/批、≤4/日、间隔≥2h；发送有节流。
7. **微信 4.x 自绘输入框**：`mmui::ChatInputField` 读不回正文 → 写入校验必然失败（robot 绕开）。
8. **微信 4.2 没有 UIA 树**：整窗只有 1 个 `MMUIRenderSubWindowHW`，所有 UIA 方案失效。
9. **暂停是文件标记**：`data/task_control/stop.flag`，只应影响当前这一轮。
10. **诊断包的 UIA 探针会挂死打包**：`_probe_tree_backends` 在窗口卡住时阻塞几十秒。

## 四、robot 当前越界的地方（要收回来）

| robot 现在的做法 | 应该改成 |
|---|---|
| 自己实现搜索框输入 + 回车 + 轮询 | 调用引擎的 wxid 搜索 + `_verify_local_send_chat` |
| 自己判断"点第几个搜索结果" | 只用 `联系人` 分组的第一条匹配（引擎已有） |
| 自己判断群/单聊 | 用引擎 `chat_type` + 库里 `wechat_peers` |
| 自己的发送校验（8s 轮询界面文本） | 复用 `_wxauto_visible_message_snapshot`（同一套判定） |
| 忽略限速闸门 | 保留闸门，robot 只在闸门放行后执行 |

robot 真正该保留的只有两件：

1. **发送环节**：微信 4.x 输入框读不回时，用"清空 → 粘贴 → 回车 → 回读"完成发送（已验证）。
2. **恢复环节**：确认当前会话 == 目标 / 窗口是否无响应 / 是否暂停，然后**换一个引擎原语**重试。

## 五、失败模式 → 已经改到哪

| 现象 | 根因 | 状态 |
|---|---|---|
| 个微不回复（skip_group） | 预览文本像群消息 + `chat_type=unknown` 覆盖库里 friend | 已修（unknown 回落库；只对"确定是群"跳过） |
| 个微不回复（recover_circuit_open） | 按名字搜撞同名群 → `session_target_mismatch` ×3 → 熔断 | 已改为 wxid 优先搜索 |
| 写不进输入框 | 4.x 自绘输入框读不回 | 已由 robot 接管发送 |
| 暂停后没有"继续"入口 | 暂停时任务不开始 → 浮标不拉起 | 已修（暂停即拉起浮标） |
| 上传诊断 60s 超时 | 诊断包里的 UIA 探针阻塞 | 已修（移除探针 + 专用线程池） |
| 日志拿不到 | 启动清空日志 + 后端独占 | 已修（清空前留档；独立导出脚本） |

## 六、收口计划（一次做完，不再逐条试）

1. `robot.open_chat` 改为调用引擎的 wxid 搜索原语，删掉 robot 自己的搜索实现。
2. `robot.send_message` 的验证改为复用 `_wxauto_visible_message_snapshot`。
3. 四个 hook（视频号上传、微信会话修复、朋友圈、好友申请）统一成同一形状：
   `引擎原语 → 失败则 robot 观察一次 → 换原语或换参数 → 仍失败才报错`。
4. 验收（同一台真机，一次跑完）：
   - 连续 3 条自动回复（含一个同名群干扰的会话）
   - 1 次通讯录同步（含新增联系人）
   - 1 次好友申请通过
   - 1 次朋友圈发布（用测试号）
   - 全程 `native_wechat_send.jsonl` 与 `native_wechat_auto_reply.jsonl` 无 `mismatch`/`hung`

## 七、明确不做

- 不为"每条消息"做视觉识别（成本与延迟都不可接受）。
- 不在 robot 里重写通讯录/群/朋友圈（引擎已有验证与限速）。
- 不把 `_probe_tree_backends` 这类会阻塞的探针放回诊断包。
