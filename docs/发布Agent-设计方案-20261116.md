# 发布/工作流 Agent 化设计方案

日期：2026-11-16
范围：发布中心（抖音/视频号/头条/小红书/快手等）与 H5 工作流里的发布节点
目标读者：客户端/服务端研发、测试、运维

---

## 1. 背景

当前发布链路是「一个平台一份写死的 Playwright 脚本」：

- `publisher/browser_pool.py` 负责拿浏览器 context、检查登录、调度 `run_publish_task`
- `skills/<platform>_publish/driver.py` 负责具体步骤（打开发布页、切 tab、上传、填文案、声明、点发布、校验）
- `backend/app/api/publish.py` 负责任务落库、并发锁、`need_login` 判定
- `backend/app/services/publish_plan_runner.py` 负责定时计划到点触发
- `backend/app/api/h5_chat_channel.py` 的 workflow 节点复用同一批 driver

问题不在"没有自动化"，而在**没有恢复能力**：

1. 选择器/文案一变，第一步不符预期就 `return ok:False`；
2. 弹层、风控页、shadow DOM 重建后，旧 handle 失效，脚本继续按原路径走；
3. 失败原因只能靠人看日志/截图，无法自己换一条路；
4. 平台改版后要人工改代码、发版，周期以天计。

结果：发布成功率不稳定，用户看到的是"又失败了"，研发看到的是"又是选择器"。

---

## 2. 目标与非目标

### 2.1 目标

1. 发布成功率可观测、可恢复：常见页面变化不再直接失败；
2. 失败时自动"观察 → 判断 → 换路 → 验证"，而不是卡死；
3. 恢复成功的路径可沉淀，第二次变确定性执行（不重复烧 LLM）；
4. 所有入口（手动发布、定时计划、H5 工作流）共享同一套能力；
5. 全过程可审计、可回放、可回滚。

### 2.2 非目标

1. 不让模型自由点击「发布/删除/支付/切换账号」；
2. 不追求"任意网站通用 Agent"，只服务我们支持的平台；
3. 不改变现有业务语义（素材、文案、声明、定时、台账去重）；
4. 不把 LLM 放进正常路径（正常路径必须零 LLM 调用）。

---

## 3. 现状拆解（改造落点）

以抖音发布为例，driver 的阶段可以统一抽象为：

| 阶段 stage | 关键动作 | 现有失败点 |
|---|---|---|
| `login` | 打开创作者中心，判断登录态 | 跳登录页、cookie 失效 |
| `open_editor` | 进入上传/发布页，切到视频 tab | 入口改版、tab 文案变化 |
| `upload` | set_input_files / file chooser | input 重建、超时、静默忽略 |
| `editor_fill` | 标题、描述、话题、封面 | 编辑器未就绪、富文本差异 |
| `declare` | 自主声明/原创声明 | 选项文案变化 |
| `publish` | 点发布、等结果 | 按钮禁用、二次确认弹层 |
| `verify` | 成功 toast / 作品列表出现 | 判定口径变化 |

> 视频号还有 shadow DOM（wujie）与"删除按钮数=2"这类挂载判定；头条/小红书/快手结构类似，只是选择器不同。

Agent 的接入点就是这些 stage 的失败分支，而不是重写整个 driver。

---

## 4. 总体架构

```
┌──────────────────────────────────────────────────────────┐
│ Director（确定性编排，现有 publish.py / publish_plan_runner）│
│  - 选账号、并发锁、计费、任务状态、台账去重                    │
└───────────────┬──────────────────────────────────────────┘
                │ run_publish_task(platform, stage)
┌───────────────▼──────────────────────────────────────────┐
│ Skill（现有 driver：确定性步骤 + 校验）                      │
│  - 正常路径不调用 LLM                                       │
│  - 每步产出 StepResult(ok, expect, observed)               │
│  - 失败 → 交给 Agent.recover(stage, goal)                  │
└───────────────┬──────────────────────────────────────────┘
                │ 仅在失败/未知态
┌───────────────▼──────────────────────────────────────────┐
│ Agent（新增 publisher/agent/）                              │
│  Observer → Planner(LLM) → Executor → Verifier → Memory    │
│  - 动作白名单、步数/时间/费用预算、置信度门槛                  │
└───────────────┬──────────────────────────────────────────┘
                │ 结构化动作
┌───────────────▼──────────────────────────────────────────┐
│ Executor（Playwright 原语，复用现有 CDP context）            │
└──────────────────────────────────────────────────────────┘
```

关键原则：

1. **确定性优先**：driver 固定路径 > 学到的路径 > LLM 规划；
2. **LLM 只做"下一步该干嘛"**，不做长文本生成，不做最终发布；
3. **每一步都可验证**，验证失败视为这一步没做；
4. **预算是硬约束**：超预算立即停止并上报。

## 5. 组件设计

### 5.1 Observer（观察）

输入：`page`、`stage`、`recent_actions`

输出（结构化，限制体积）：

```json
{
  "url": "https://creator.douyin.com/creator-micro/content/upload",
  "title": "抖音创作者中心",
  "stage": "upload",
  "ax_nodes": [
    {"role": "button", "name": "上传视频", "bbox": [820, 360, 120, 40], "enabled": true},
    {"role": "textbox", "name": "作品标题", "value": "", "bbox": [420, 520, 600, 36]}
  ],
  "visible_text": "支持上传视频 拖动到此处...",
  "screenshot": "jpeg_base64（最长边 1024，q=70）",
  "console_errors": ["..."],
  "last_actions": ["click 上传视频 → timeout"]
}
```

实现要点：

- 优先 `Accessibility.getFullAXTree`（CDP），过滤为可交互节点（button/textbox/link/tab/combobox），最多 80 个；
- 截图缩放到 1024 长边、JPEG 70，约 100~200KB；
- 页面签名：`sha256(platform|stage|url_path|关键节点 role+name 的前 40 个)`，用于记忆与去重。

### 5.2 Planner（决策）

- 输入：目标（stage 的 success 定义）、观察、历史动作、当前预算；
- 输出必须是 JSON（不接受自然语言）：

```json
{
  "thought": "上传入口在 shadow DOM，先点上传区域触发 file chooser",
  "action": "click",
  "target": {"by": "text", "value": "上传视频"},
  "expect": {"kind": "filechooser"},
  "confidence": 0.86
}
```

- 动作枚举：`click / type / set_files / press / wait_for / scroll / close_overlay / reload / screenshot / abort`
- `target.by`：`text | role | selector | point`，优先语义定位，坐标只做最后兜底；
- 置信度 < 0.6 直接 `abort`，转人工/通知；
- 每次决策带 `budget`（剩余步数/时间/调用次数），模型必须在预算内选动作。

### 5.3 Executor（执行）

- 只执行白名单动作；
- 统一超时（click 8s、wait 15s、set_files 60s）；
- 失败返回结构化错误（不是抛异常到顶层）；
- 不执行任意 JS，不访问非平台域名。

### 5.4 Verifier（验证）

每个 stage 定义不变量（invariants），执行动作后必须验证：

| stage | 不变量 |
|---|---|
| login | 未跳登录页、账号菜单存在 |
| open_editor | 编辑器容器出现、发布按钮存在 |
| upload | 视频元素/删除按钮数 ≥ 1（视频号=2）、上传进度消失 |
| editor_fill | 标题/描述输入框值 = 期望值 |
| declare | 声明选项选中态 = 期望 |
| publish | 成功 toast / 跳转作品管理 / 列表出现新作品 |

验证同时看 DOM 与截图（视觉校验：按钮是否被遮挡/置灰）。

### 5.5 Memory（记忆）

- `publisher/learned_routes.json`：

```json
{
  "douyin|upload|sig_ab12": {
    "actions": [{"action": "click", "target": {"by": "text", "value": "上传视频"}}],
    "success_count": 3,
    "fail_count": 0,
    "updated_at": "2026-11-16T12:00:00+08:00"
  }
}
```

- 命中签名时先走 learned route（确定性），失败再降级 LLM；
- 连续成功 3 次标记 `stable=true`，可建议合并进 driver；
- 失败 2 次自动失效，避免"学错路"。

### 5.6 Trace（审计）

每次恢复记录：

```
trace_id, user_id, platform, stage, page_signature,
observation(截图路径/摘要), actions[], llm_calls[], results[], duration, cost
```

- 本地：`publisher/agent_traces/<date>/<trace_id>.jsonl` + 截图；
- 上传：仅随诊断包上传，默认不主动上报；
- 支持按 trace 回放（离线复现）。

### 5.7 Safety（安全）

- 动作白名单按 stage 配置；
- 永久禁止：最终「发布」、删除、支付、切换账号、任意 JS；
- 最终发布由确定性代码触发，且必须满足：
  - 预览校验通过（标题/素材/声明与期望一致）；
  - 任务来自用户确认或定时策略；
- 频控：同一账号同一时间只允许一个 Agent 会话；
- 预算：单次恢复最多 12 步 / 90 秒 / 3 次 LLM 调用；
- 内容安全：截图可能含用户内容，默认只本地保存；需要云端决策时走加密通道，并在隐私政策说明。

## 6. 错误分层与处理策略

| 错误码 | 例子 | 处理 |
|---|---|---|
| `NET_TIMEOUT` | 连接超时、读写超时 | 指数退避重试（不调 LLM） |
| `LOGIN_LOST` | 跳登录、二维码 | 立即停止，标记 `need_login`，通知 |
| `SELECTOR_MISSING` | 元素找不到 | Agent 接管（找新入口） |
| `PAGE_CHANGED` | 文案/结构变化 | Agent 接管 + 记忆 |
| `OVERLAY_BLOCKED` | 弹层遮挡 | Agent 先关弹层再重试 |
| `MEDIA_NOT_ATTACHED` | 视频号"请上传视频" | Agent 重新上传 + 校验 |
| `UPLOAD_REJECTED` | 平台拒绝素材 | 解析平台文案，直接报原因 |
| `VALIDATION_FAILED` | 文案超长/必填缺失 | 规则修正后重试 |
| `UPSTREAM_5XX` | 上游 500/503 | 切通道或报运维 |
| `RATE_LIMITED` | 429 | 退避 + 切通道 |
| `RISK_CONTROL` | 验证码/滑块 | 停止，人工处理，不绕过 |
| `UNKNOWN` | 其他 | Agent 观察一轮，仍失败则上报 |

## 7. 与现有代码的集成

### 7.1 新增目录

```
publisher/agent/
  __init__.py
  observer.py      # 截图 + AX 树 + 页面签名
  planner.py       # LLM 调用与 JSON 解析
  actions.py       # 白名单动作执行
  verifier.py      # stage 不变量
  memory.py        # learned_routes 读写
  budget.py        # 步数/时间/费用
  trace.py         # 审计与回放
  loop.py          # recover(stage, goal) 主循环
```

### 7.2 driver 改造方式（最小侵入）

在每个失败分支：

```python
if not attached:
    recovered = await agent.recover(page, stage="upload", goal="视频已挂载")
    if recovered.ok:
        attached = True
    else:
        return {"ok": False, "error": ..., "need_login": recovered.need_login}
```

- 只在 stage 失败时调用；
- 恢复成功继续原流程，不改变后续逻辑；
- 恢复失败保留原错误 + agent 诊断信息。

### 7.3 服务端支持

新增 `POST /api/agent/browser-decide`（云端）：

- 入参：platform、stage、observation、history、budget；
- 出参：结构化动作 JSON；
- 负责：模型选择、提示词版本、限流、审计、计费（可选）；
- 好处：key 不下发客户端、提示词可热更新、可按用户灰度。

### 7.4 入口覆盖

- 手动发布：`/api/publish` → `run_publish_task`
- 定时计划：`publish_plan_runner` → 同一个 `run_publish_task`
- H5 工作流：`h5_chat_channel` 的发布节点 → 同一个 driver
- 数字人/剪辑大师套模板后的发布：同上

只要改 driver，所有入口自动受益。

## 8. 成本模型

- 正常发布：0 次 LLM；
- 失败恢复：平均 1~2 次决策，单次约 3k tokens（截图 1.2k + AX/文本 1k + 输出 0.3k）；
- 按 5% 发布失败率、每天 200 次发布估算：每天约 10~20 次决策，成本可忽略；
- 硬上限：单账号每天最多 50 次决策，超限只记录不决策。

---

## 9. 可观测性

指标（按平台/stage）：

- 发布成功率、失败率、`need_login` 率；
- 恢复成功率、平均恢复步数、平均耗时；
- LLM 调用次数/成本、learned route 命中率；
- 误动作率（执行了但验证不通过）；
- 人工介入率。

看板：服务端 `/api/publish/metrics` 扩展或独立 `agent_metrics`。

## 10. 实施计划

### P0（1~2 天）：可观测，不接 LLM

- 失败时保存截图 + 页面签名 + 错误分类；
- 统一错误码；
- 诊断包里带 agent 观测数据。

验收：任意一次失败能回答"卡在哪一步、页面长什么样、当时 DOM 有哪些可交互元素"。

### P1（3~5 天）：两个高频点接恢复

- 抖音 `upload`、视频号 `upload / editor_fill`；
- 只做 Agent 恢复，不碰发布按钮；
- Feature flag：`LOBSTER_PUBLISH_AGENT=off|observe|recover`，按平台灰度。

验收：人为制造 3 类故障（改文案、弹层、input 重建），恢复成功率 ≥ 70%，无误发布。

### P2（3~5 天）：记忆与自学习

- learned_routes；
- Trace 回放与回归用例；
- 稳定路径合并回 driver 的流程。

验收：同一故障第二次不再调用 LLM；回归用例全部通过。

### P3（1~2 周）：全平台 + 目标驱动

- 头条/小红书/快手接入；
- 新平台只写"目标 + 不变量"，步骤由 Agent 规划；
- 发布前人工确认策略。

验收：新平台接入时间从"2~3 天"降到"半天"，发布成功率不低于现有。

## 11. 测试矩阵

| 维度 | 用例 |
|---|---|
| 平台 | 抖音 / 视频号 / 头条 / 小红书 / 快手 |

| 预算 | 超步数、超时、LLM 连续低置信度 |

## 12. 风险与回滚

| 风险 | 应对 |
|---|---|
| LLM 误点/误判 | 白名单 + 不变量验证 + 发布确认 |
| 截图隐私 | 默认本地保存；云端决策加密；隐私政策说明 |
| 成本失控 | 预算 + 每日上限 + 只失败时调用 |
| 学习到错误路径 | fail_count 自动失效 + 人工复核 |
| 平台风控 | 保持人类节奏（现有 human delay），不高频重试 |
| 回滚 | Feature flag 一键回 `off`，不改 driver 主流程 |

## 13. 附：Planner Prompt 骨架

```
你是浏览器操作助手，只输出 JSON，不输出解释性文本。
目标：{goal}
平台：{platform} 阶段：{stage}
预算：剩余 {steps} 步 / {seconds} 秒 / {llm_calls} 次
观察：{observation_json}
历史：{history}
允许动作：click/type/set_files/press/wait_for/scroll/close_overlay/reload/screenshot/abort
禁止：发布、删除、支付、切换账号、执行 JS
规则：
1. 优先用语义定位（text/role），坐标只做兜底；
2. 每步必须给 expect，便于验证；
3. 置信度 < 0.6 输出 abort；
4. 不要在同一个失败动作上重复超过 2 次。
输出：{"thought":"...","action":"...","target":{...},"expect":{...},"confidence":0.0}
```

## 14. 结论

- 不改业务语义，只在失败点插入 Agent；
- 正常路径零成本、零延迟；
- 失败可恢复、可学习、可审计；
- 最终发布仍由确定性代码控制，风险可控。

先做 P0，再按 P1 的两个高频点上线，是投入产出比最高的路径。
